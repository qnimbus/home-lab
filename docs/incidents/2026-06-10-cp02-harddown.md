# Incident — cp-02 silent hard-down #4 (2026-06-10 ~19:41 UTC)

**First forensically-captured occurrence.** The off-node vitals capture armed in commit `bca4cee`
(node-exporter @10s on durable `ceph-block` Prometheus) + the live `scripts/cp02-watch.sh` alerter
caught this one with a dense pre-crash record — the first time a cp-02 hard-down has *not* been a
post-reboot blind spot.

## Signature

cp-02 went **hard-down at ~19:41:01 UTC**: node `NotReady`, kubelet/apid unreachable. Both network
paths confirmed dead from **two independent vantage points** — mgmt side: Prometheus `up=0` (scrape
at `10.60.0.202:9100`) + 100% mgmt ping loss; storage side: **Ceph marked osd.3+osd.4 `down` and
mon-c out of quorum** (the OSDs/mon live on cp-02's `10.200.0.0/24` X520 bond). Whole-machine freeze
⇒ every NIC dark at once. Identical to the 2026-06-02 ×2 and 2026-06-10 (#3) silent downs.
**Distinct from the 2026-06-01 thermal trip** — this one happened cold (board 52 °C).

> **Evidence caveat:** do NOT cite a devcontainer ping to `10.200.0.202` as proof the storage NIC
> died — the devcontainer has **no route to the `10.200.0.0/24` storage VLAN** (verified: cp-01,
> cp-03, and TrueNAS storage IPs are all unreachable from it; only a Docker-bridge default route
> exists). Storage-side liveness must come from Ceph/the nodes, not a local ping.

## Pre-crash telemetry (last successful scrapes, 19:38:00 → 19:39:50 UTC)

| Metric | Behaviour up to the freeze | Reading |
|--------|----------------------------|---------|
| Board/VRM (`nct6683` temp2) | **flat** | 51–54 °C |
| CPU package (`coretemp`) | **flat, idle** | 47–50 °C |
| `MemAvailable` | **rock-steady, even rising** | ~62.2–62.4 GB |
| `load1` | trivial, mild uptick | 0.20 → 0.57 |
| Per-NIC errs/drops (all devices incl. eno1, bond0, enp1s0f0/f1, bond-storage) | **all zero** | 0 |

Then: instantaneous 100% dark on both NICs, no intervening degradation on any series.

## Interpretation — competing hypotheses eliminated

The value of the armed capture is **what it rules out**:

- **NOT thermal** — board flat at 51–54 °C, 20 °C below the ~72 °C BIOS trip. Decouples this from
  the (separately-confirmed) cp-02 degraded-VRM thermal-path fault.
- **NOT OOM / memory leak** — `MemAvailable` steady at ~62 GB to the last sample.
- **NOT NIC/link degradation** — zero errs/drops on every interface; the NICs went healthy →
  dark in one instant, not via a ramp. Rules out an X520 link fault as the *initiator*.
- **NOT load/runaway** — load1 ~0.5 on a 6-core part is ~5 % busy.

"Completely healthy → instant total freeze, no precursor in any telemetry" is the fingerprint of a
**hard CPU/kernel wedge** — exactly what a **non-ECC RAM bit-flip** into kernel code / page tables
produces. A single flipped bit corrupts execution **without** moving the aggregate `MemAvailable`
counter, so steady memory is *consistent with* (not evidence against) the RAM theory. Conclusion:
**no telemetry will ever predict this** — resolution is offline (MemTest86+) or hardware
(reseat/swap RAM, then the unit).

## Cluster blast-radius (all expected, data safe)

- **Ceph `HEALTH_WARN`** (not `ERR`): osd.3+osd.4 (cp-02) down, mon-c out. **mon quorum holds 2/3
  (a,b)**; mgr `a` active. 33 PGs `active+undersized+degraded` — **still serving at 2 replicas**
  (`min_size=2` satisfied). 33 % "degraded" = the 3rd copy that lived on cp-02. Stays undersized
  (failure domain `zone`, no 4th zone to rebuild into) until cp-02 returns, then recovers the delta.
- **etcd**: 2/3 quorum (apiserver responsive ⇒ quorum intact).
- **Workloads**: zero stuck pods cluster-wide. RWO-pinned volumes resume on cp-02's return.

## Recovery & next action

M920Q has **no BMC/IPMI** → recovery is a physical power-cycle; kernel ring buffer wipes on reboot
and netconsole is unviable under UKI, so there is nothing further to capture from the dead node.

**The node is already offline and must be physically touched to recover → this is the ideal,
near-zero-marginal-cost moment to boot MemTest86+ instead of straight back into Talos.** It directly
tests the now-leading theory. If MemTest passes clean, escalate to reseat RAM + X520, then swap.

See memory `project-cp02-outage-investigation` and `docs/ROADMAP.md → cp-02 Thermal Stability`.
